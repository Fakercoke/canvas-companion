# Source-grounded assignment workflow

Use for a substantive assignment request. Scale to the task; do not force every small question through a full essay pipeline. Continue actions already authorized instead of asking for approval at each stage.

## 1. Build a compact brief from real sources

Read the assignment page, attachments, rubric, relevant announcements and AI instructions. Capture topic choices, required sources, task verbs, length/exclusions, format, due date/timezone and submission target. For each rule retain its source. Mark missing rules as unknown rather than using generic university rules as substitutes. A rubric is not a promise of a mark.

## 2. Read for this assignment

Prioritise required/core readings and relevant course weeks before optional outside literature when the brief calls for that. Build a small evidence map: claim or concept; supporting source/location; full-text/partial/abstract access; relevance to a rubric criterion; limitations. Actually read accessible text, not only citations. Do not cite an inaccessible passage as verified. If a required source is unavailable, finish other useful work and clearly mark the unresolved dependency.

## 3. Develop the student's response

For personal reflection, ask one substantive question when needed, for example which claim the student agrees with and why. Use their answer and verified materials; never invent experience or say they read a source merely because the agent did. Present a defensible central question/argument with the evidence, counterargument and limitations needed by the task. Produce the requested output within the course's permitted AI scope; distinguish drafting from editing in the actual-use log.

## 4. Review like a reader using the published rubric

Evaluate each criterion against a concrete section or passage of the draft. Use a compact table: criterion; evidence in the draft; gap; proposed correction. Prioritise missing requirements, unsupported arguments, misrepresented readings and citation errors before style. Critically test the argument and its strongest counterargument rather than just praising the work. Apply authorized revisions, then recheck affected criteria. Do not impersonate the teacher, guarantee grades, invent a numeric mark or claim an independent review when the same agent self-reviewed. Use an independent agent only when authorized/available.

## 5. Package the deliverable

Check the actual final artifact: length using the specified counting rules, required sections, citations/reference correspondence, file format, readable layout and final filename. Include the declaration in the location/format required by the course, using [declaration workflow](ai-declaration.md). Mark checks that could not be performed. If word-count rules are unclear, report counts with and without the declaration rather than invent an exemption.

Deliver the file and a short explanation of material remaining gaps. When submission is explicitly requested, use the submission recipe in [tasks.md](tasks.md); do not upload an intermediate draft because its filename looks plausible. Keep artifacts and evidence notes outside the public Skill folder.
